## 1. 目的・背景
バッテリ約 1000 個について、平常時（無負荷）の電圧を 1 個ずつ測って記録し、一覧（CSV と Excel）に残したい。
INA226_Monitor は 1 つの対象を時間の流れで測るソフトで、「多数の個体を 1 点ずつ測って並べる」作業には向かないため、
受信・画面の部品を転用して、この作業専用のソフトを作る。

## 2. スコープ
### やること
- INA226_Monitor と同じ Arduino（スケッチ・配線そのまま）からの電圧の受信
- 現在の電圧のリアルタイム表示（バッテリが繋がっているかどうかが分かる）
- 記録ボタン（または Space／Enter キー）で、その時点のバッテリの電圧を 1 件記録する（5 回測定の中央値、F-04）
- 記録ごとの連番の自動採番、上下限による OK／NG 判定
- 記録の一覧表示と、記録した電圧の分布グラフ
- 直前の記録の取り消しと、選んだ番号の測り直し
- 記録のたびに作業ファイルへ自動保存し、異常終了しても続きから再開できること
- 最後に CSV と Excel（.xlsx）へ出力
- Windows 用 exe として配布（管理者権限なしで動作）

### やらないこと（明示的に対象外）
- 負荷をかけた状態の測定、内部抵抗の測定、時間変化（波形）の記録 → INA226_Monitor を使う
- 電流値の記録（無負荷のため。表示もしない）
- 複数台（複数の Arduino）の同時測定
- バーコード・QR コードでのバッテリ識別（将来の拡張。今回は連番。Q-07）
- 保存済み CSV／Excel を読み込んで再表示・編集する機能（作業ファイルからの再開は F-08 で行う）
- ネットワーク・データベースへの保存

## 3. 利用者と利用シーン
- 利用者：福井と開発メンバー（ソフトウェアに詳しくない人も含む）。UI は日本語。
- 利用手順：
  1. Arduino と INA226 を接続し、exe を起動する。COM ポートを選んで「接続」を押す
  2. 新しいロットを始める：ロット名・測定者・上下限・開始番号を入れて「開始」（前回の値が入っている）
  3. バッテリを INA226 の測定端子に繋ぐ → 画面の電圧が安定したら「記録」（または Space／Enter）
  4. 画面に「No.12  3.8125 V  OK」のように結果が大きく出る → バッテリを外し、次のバッテリを繋いで 3 を繰り返す
  5. 間違えたら「1 つ前を取り消す」（Ctrl+Z）、または一覧で番号を選んで「この番号を測り直す」
  6. 全部終わったら「出力」→ 保存先を選ぶ → CSV と Excel ができる
- 1 ロットの規模：最大 1000 件（上限は設けないが、性能は 2000 件まで保証。8 章）
- 1 件の作業時間の目安：3〜5 秒（ソフト側の記録処理は 0.5 秒以内）
- 作業は途中で休憩・PC の再起動をはさむことがある（F-08 で再開）

## 5. 外部インタフェース
### 5.1 ハードウェア・通信
INA226_Monitor と同じ。違いは、送信周期を 40 ms に設定する点と、電圧（bus_V）だけを使う点。

| 項目 | 値 |
|---|---|
| 接続機器 | Arduino UNO（または Nano）＋ M5Stack Unit INA226-1A（シャント 80 mΩ、I2C 0x41） |
| 測定対象の接続 | バッテリの＋を INA226-1A の測定側の電圧入力（バス電圧の端子）、−を測定側の GND に繋ぐ（Q-02 で配線を確定） |
| 測定範囲 | 0〜36 V（INA226 のバス電圧の範囲）。分解能 1.25 mV |
| 通信方式 | USB シリアル（仮想 COM ポート） |
| ポート / ボーレート / データ長 / パリティ / ストップビット | ユーザーが選択 / 115200 / 8 / なし / 1 |
| 送信周期 | **40 ms**（接続時にアプリが `INTERVAL 40` を送る。応答 `# interval_ms=40 avg=16`）。応答が無い古いスケッチでは 50 ms のまま使う |
| フレーム形式 | ASCII、カンマ区切り、1 行 1 サンプル、行末 CRLF |
| Arduino スケッチ | `reuse/firmware/ina226_logger/ina226_logger.ino`（INA226_Monitor v1.2.1 と同じ。変更しない） |

受信行の種類（INA226_Monitor と同じ判定。`reuse/ina226_monitor/protocol.py` をそのまま使う）：
| 種類 | 判定 | 扱い |
|---|---|---|
| ヘッダ行 | `time_ms,bus_V,shunt_uV,current_mA` と一致 | 読み飛ばす（受信スレッドが周期変更コマンドを送る） |
| コメント行 | `#` で始まる | 読み飛ばし、ステータス欄に表示。`# interval_ms=…` は周期の応答、`# ina226_logger fw=2` はスケッチの名乗り |
| データ行 | カンマ区切り 4 列で、すべて数値 | 2 列目 bus_V（V）だけを使う |
| 不正行 | 上記以外 | 読み飛ばし、不正行数に加算 |

受信データ例（バッテリ 3.81 V を繋いだ状態の想定。INA226_Monitor の実データと同じ形式）:
```
# ina226_logger fw=2
# I2C scan...
#  found 0x41
time_ms,bus_V,shunt_uV,current_mA
# interval_ms=40 avg=16
1290,3.8125,-7.5,-0.094
1330,3.8125,-10.0,-0.125
1370,3.8113,-7.5,-0.094
1410,3.8125,-7.5,-0.094
1450,3.8138,-10.0,-0.125
```
バッテリを外した状態では bus_V は 0.0000 付近になる（実データ：`188002,0.0000,-10.0,-0.125`）。

| ファイル | 方向 | 形式 | 文字コード / 改行 | 区切り |

| `<基名>.xlsx` | 出力（F-09） | Excel ブック | - | - |
| `%LOCALAPPDATA%\INA226_BatteryChecker\lots\<ロットID>.csv` | 作業ファイル（記録のたびに追記。F-08） | CSV（下の列定義と同じ） | UTF-8（BOM 付き）/ CRLF | カンマ |

| `%APPDATA%\INA226_BatteryChecker\app.log` | 出力（エラー・警告。最大 1 MB × 3 世代） | テキスト | UTF-8 | - |

- 基名：`<ロット開始日 YYYYMMDD>_<ロット名>_電圧記録`（例：`20261106_LOT-A12_電圧記録`）。使えない文字・空白は `_` に置き換え、同名があれば `_2`, `_3` …（`reuse/ina226_monitor/filename.py` の `sanitize`・`unique_base_name` を使う）。
- ロットID：`<ロット開始日時 YYYYMMDD_HHMMSS>`（作業ファイル名。同じ秒なら `_2`）。

CSV 列定義（作業ファイルと出力 CSV で同じ。1 行目は列名行、2 行目からデータ。番号順に並べる）:
| 列名 | 型 | 単位 | 例 | 備考 |
|---|---|---|---|---|
| no | 整数 | - | 12 | 連番（F-05） |
| voltage_V | 実数（小数 4 桁） | V | 3.8125 | 記録値＝5 回の中央値（F-04） |
| judge | 文字列 | - | OK | `OK` / `NG_LOW`（下限未満）/ `NG_HIGH`（上限超え） |
| min_V | 実数（小数 4 桁） | V | 3.8113 | 5 回のうち最小 |
| max_V | 実数（小数 4 桁） | V | 3.8138 | 5 回のうち最大 |
| measured_at | 文字列 | - | 2026-11-06 14:30:17 | 記録した PC 時刻 |
| remeasured | 整数 | - | 0 | 測り直した回数（F-07） |
| note | 文字列 | - | ばらつき大 | 自動の注意書き（F-04）。無ければ空 |

出力 CSV のサンプル（先頭数行）:
```

1,3.8125,OK,3.8113,3.8138,2026-11-06 14:30:05,0,
2,3.7950,OK,3.7950,3.7963,2026-11-06 14:30:09,0,
```

Excel（.xlsx）の内容（「わかりやすく」＝開いてすぐ判定結果と分布が分かること）:
| シート名 | 内容 |
|---|---|
| 記録 | 列：No／電圧 [V]／判定／最小 [V]／最大 [V]／記録日時／測り直し／備考。見出しは太字・塗り（付録 B の色）、1 行目を固定（ウィンドウ枠の固定）、オートフィルタ付き。NG の行は判定セルを赤（背景 #A3282C・白字）。電圧は表示形式 `0.0000`。列幅は内容に合わせる |
| 集計 | ロット名・測定者・開始日時・終了日時・下限・上限・件数・OK 数・NG 数（下限未満／上限超え）・OK 率・平均・中央値・最小（No 付き）・最大（No 付き）・標準偏差。電圧の度数分布表（区間 10 mV、または 13 章 Q-05）と、その棒グラフ（openpyxl のグラフ） |
| 条件 | ソフト名と版、スケッチの版（名乗りが無ければ「不明」）、送信周期、記録方法（「5 回測定の中央値」）、COM ポート |

## 6. 機能要件
### F-01: COM ポート選択・接続
- 入力：PC の COM ポート一覧、「更新」「接続」「切断」ボタン
- 処理：INA226_Monitor の F-01 と同じ一覧表示（`reuse/ina226_monitor/serial_io.py` の `list_ports`）。前回のポートを初期選択。「接続」でポートを開き、受信を始める（`SerialReader(port, queue, interval_ms=40)`。周期変更の送り直し・リセットされないボードへの送信も含めてそのまま使う）。
- 出力：接続状態（ステータス欄：未接続／接続中：COM7）
- 異常時：ポートが無い → 「Arduino が見つかりません。USB の接続を確認してください」、開けない → 「COMx を開けません。シリアルモニタなど他のソフトを閉じてください」。周期変更の応答が無い → 「Arduino のスケッチが周期変更に対応していません（50 ms で記録します）」をステータス欄に出し、そのまま使う。

### F-02: ロットの開始
- 入力：ロット名（必須、30 文字まで）、測定者（任意、30 文字まで）、下限 [V]・上限 [V]（必須、小数 3 桁まで、下限 < 上限）、開始番号（既定 1）、メモ（任意、複数行）
- 処理：「新しいロット」→ 入力ダイアログ → 「開始」で作業ファイル（CSV・JSON）を作り、記録できる状態にする。ロット名・測定者・上下限は前回の値を初期表示する。
- 出力：作業ファイル、画面上部のロット表示（例：`LOT-A12 ／ 下限 3.600 V・上限 4.200 V`）
- 異常時：必須項目が空・下限 ≧ 上限 → その欄を赤枠にして「開始」を押せない。作業ファイルを作れない → 「作業ファイルを作れません（<パス>）」と表示し、ロットを始めない。

### F-03: 電圧のリアルタイム表示と接続検知
- 入力：受信したデータ行の bus_V
- 処理：最新の電圧を 200 ms ごとに大きく表示する（小数 4 桁、等幅、右寄せ。INA226_Monitor の電流バッジと同じ見た目で、中身を電圧にする）。
  - 電圧が **接続判定電圧（既定 0.5 V。Q-03）未満** なら「バッテリ未接続」と表示し、記録ボタンを無効にする。
  - 接続判定電圧以上なら「接続中」。直近 0.5 秒（約 12 個）の最大−最小が **安定幅（既定 5 mV。Q-04）以内** なら「安定」、超えていれば「変動中」と表示する（記録はできる）。
- 出力：電圧表示、接続状態の表示
- 異常時：開始後 5 秒間データ行が来ない → 「データが届いていません」（INA226_Monitor と同じ）。

### F-04: 記録（5 回測定の中央値）
- 入力：「記録」ボタン、または Space／Enter キー（入力欄に文字カーソルがあるときは文字入力を優先し、記録しない）
- 処理：
  - 押した**後に**届いたデータ行を 5 個集め（40 ms 周期で約 0.2 秒、50 ms なら約 0.25 秒）、bus_V の中央値を記録値とする。最小・最大も残す。
  - 集めている間は「測定中…」と表示し、ボタン・キーの再入力は無視する。
  - 記録値を上下限で判定する（下限 ≦ 値 ≦ 上限 → OK、値 < 下限 → NG_LOW、値 > 上限 → NG_HIGH）。境界ちょうどは OK。
  - 5 個の最大−最小が安定幅（Q-04）を超えた場合は記録したうえで note に「ばらつき大」と入れ、結果表示に注意マークを出す。
  - 記録したら、すぐ作業ファイルに 1 行追記して保存する（F-08）。
  - **同じバッテリの二重記録防止**：前回の記録のあと、電圧が一度も接続判定電圧未満にならないまま（＝バッテリを外さずに）次の記録をしようとしたら、「前回と同じバッテリのようです。もう一度記録しますか？」（記録する／やめる）を出す（Q-06）。
- 出力：記録 1 件、結果表示（`No.12　3.8125 V　OK` を大きく。OK は緑系、NG は赤 #A3282C）、短い音（OK と NG で音を変える。Q-08）
- 異常時：
  - バッテリ未接続（F-03）→ 記録しない。「バッテリが接続されていません」
  - 1 秒以内に 5 個そろわない → 記録しない。「データを受信できませんでした。もう一度記録してください」
  - 5 個の途中で接続判定電圧未満が混ざった（外れた）→ 記録しない。「測定中にバッテリが外れました」
  - 作業ファイルに書けない → 画面上の記録は残し、「作業ファイルに書き込めません」と赤で表示。次の記録時に未保存分をまとめて書き直す（INA226_Monitor の一時ファイルと同じ考え方）

### F-05: 連番
- 処理：記録ごとに「次の番号」を 1 増やす。開始番号はロット開始時に決める。画面に「次は No.13」と大きく表示する。
- 取り消し（F-06）をすると次の番号は 1 戻る。測り直し（F-07）では番号は変わらない。
- 番号は欠番・重複なく連続すること（取り消し・測り直しの後も）。

### F-06: 直前の記録の取り消し
- 入力：「1 つ前を取り消す」ボタン、または Ctrl+Z
- 処理：確認（「No.12（3.8125 V）を取り消しますか？」はい／いいえ）の後、最後の 1 件を削除し、作業ファイルにも反映する。何件でも続けて取り消せる。
- 異常時：記録が 0 件 → ボタン無効。

### F-07: 選んだ番号の測り直し
- 入力：一覧で行を選ぶ → 「この番号を測り直す」→ そのバッテリを繋ぐ → 「記録」
- 処理：測り直しモードの間は、結果表示に「No.5 を測り直します」と出す。記録すると、その番号の値・判定・日時を置き換え、remeasured を 1 増やす。次の番号は変わらない。測り直しは「やめる」で取り消せる。
- 出力：置き換えた記録、作業ファイル

### F-08: 自動保存と再開
- 処理：
  - 記録・取り消し・測り直しのたびに、作業ファイル（CSV）を書き換えるか追記し、ファイルを閉じる（OS のキャッシュに残さないよう flush する）。ロット情報（ロット名・測定者・上下限・開始番号・開始日時・メモ・終了したか）は JSON に保存する。
  - 起動時に、終了していない（出力も「ロット終了」もしていない）作業ファイルがあれば「前回のロット（LOT-A12、352 件、最後は No.352）が途中です。続けますか？」（続ける／新しいロット／あとで）を出す。「続ける」で一覧・次の番号・上下限を元に戻す。
  - 「ロット終了」で作業ファイルを終了扱いにする（ファイルは 30 日残す。Q-09）。
- 異常時：作業ファイルの最終行が途中で切れている → その行を除いて再開し、「最後の 1 件（No.353）が壊れていたため除きました」と表示する。

### F-09: 出力（CSV と Excel）
- 入力：「出力」ボタン、保存先フォルダ（前回のフォルダを初期表示）
- 処理：5.2 に従い `<基名>.csv` と `<基名>.xlsx` を保存する。記録は番号順に並べる。出力してもロットは終わらない（途中で出力して、続けて記録できる）。出力後に「ロットを終了しますか？」（終了する／続ける）を出す。
- 出力：CSV、xlsx。保存後に「保存しました：<フォルダ>」と「フォルダを開く」ボタン
- 異常時：書き込めない（Excel で開いているなど）→ 「<ファイル名> に書き込めません。Excel などで開いていないか確認してください」。片方だけ書けた場合は書けた方を消して、両方とも失敗扱いにする（INA226_Monitor の保存と同じ）。

### F-10: 一覧と分布の表示
- 処理：
  - 一覧（表）：No／電圧 [V]／判定／記録日時／備考。新しい記録が一番上に来る（降順）。NG の行は判定セルを赤。最新の行を自動で選ぶ。
  - 分布グラフ：横軸 No、縦軸 電圧 [V] の散布図（点）。上限・下限を横線で表示。OK はオレンジ系、NG は赤。記録のたびに更新。縦軸の範囲は「下限−(上限−下限)×0.2 〜 上限＋(上限−下限)×0.2」と記録値の両方が入る範囲。
  - 集計：件数・OK 数・NG 数・平均・最小・最大を、ステータス欄の上に 1 行で表示。
- 出力：画面表示

## 9. エラー処理・異常系
| 状況 | 期待する動作 |
|---|---|
| ポートが無い・開けない | F-01 の異常時 |
| 測定中に USB が抜けた | 受信を止めて「Arduino との接続が切れました」。記録済みのデータは作業ファイルに残っている。再接続すれば続けられる |
| バッテリ未接続で記録 | 記録しない（F-04） |
| 記録中にバッテリが外れた | 記録しない（F-04） |
| 同じバッテリを続けて記録しようとした | 確認を出す（F-04） |
| 作業ファイルに書けない | F-04 の異常時 |
| 出力先に書けない | F-09 の異常時 |
| アプリの異常終了・PC の電源断 | 次回起動時に F-08 で再開できる |
| 周期変更の応答が無い | 50 ms のまま使う（F-01） |
